### Detalhes dos Falhas

**H1 (⚠️ Parcial)**: O SLM entendeu a arquitetura multi-arquivo perfeitamente — nenhuma alucinação. Mas simplificou a API: em vez de validar `OrderStatus::Pending` e retornar `Result<(), String>`, fez `HashMap::remove` retornando `Option<Order>`. O teste que escreveu validou o contrato simplificado.

**H2 (❌)**: O SLM propagou corretamente em `user.rs` (adicionou campo, atualizou construtor). Mas colocou `age` como parâmetro de `UserService::new(age: u8)` em vez de `register()`, com tipo errado (`u8` vs `u32`). O teste existente `integration_test.rs` não foi atualizado, quebrando `cargo test`.

**H3 (❌)**: O SLM reinterpretou `checkout(&mut self) -> Result<Buffer, String>` como `checkout(&mut self, index: usize) -> &Buffer`. Mudou completamente a semântica (get-by-index em vez de pop-owned). O teste chamou `.is_none()` em `&Buffer`, inconsistente internamente.

## 4. Síntese Experimental

1. **Hipótese H1 Suportada Neste Benchmark**: O `RepoMap` determinístico eliminou 100% das alucinações arquiteturais (`crate::accounts`, `crate::errors`) em SLMs ≤3B.
2. **Hipótese H2 (Guided Diagnostics & Diagnostic Constraints)**: Os diagnósticos estruturados transformaram mensagens de erro em restrições operacionais focadas por arquivo.
3. **Hipótese H3 (Symbol Grounding & Pre-Mutation Semantic Guard)**: O `SemanticGuard` interceptou com sucesso tentativas de invocar métodos inexistentes (`self.store.update`) antes de qualquer mutação.
4. **Hipótese H4 (Contract-Grounded Editing)**: O `TaskContract` previne tipo primitivo errado dentro de código gerado, mas **não previne reinterpretação semântica da API** (assinatura completamente diferente do especificado).

### Falha Metodológica Revelada (H1)

O agente implementou uma API errada e depois escreveu testes que confirmavam a
própria API errada (`wrong implementation + wrong tests = cargo test ✅`).
Validação autorreferencial é falso positivo clássico. Correção estrutural na
v0.9.5: acceptance oracle definido **antes** da implementação e bloqueado contra
alteração pelo Coder (`SPEC_ORACLE`, ADR-0017).
